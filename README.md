# URL Shortener

پروژهٔ آموزشی کوتاه‌کنندهٔ لینک؛ توسعهٔ تدریجی از مبانی HTTP تا مفاهیم پیشرفتهٔ بکند.

**وضعیت فعلی: اسپرینت ۲ — کوتاه‌کنندهٔ لینک با ذخیره‌سازی در حافظه.** ساخت لینک، Redirect، اعتبارسنجی ورودی و مدیریت برخورد کدها پیاده شده‌اند. لینک‌ها با توقف یا شروع دوبارهٔ برنامه از بین می‌روند؛ PostgreSQL در اسپرینت بعد اضافه می‌شود.

## پیش‌نیاز و اجرا

- Node.js نسخهٔ ۲۴؛ نسخهٔ اصلی در `.node-version` ثبت شده است.
- pnpm نسخهٔ `12.16.1`؛ نسخهٔ مدیر بسته در `package.json` ثبت شده است.

در ریشهٔ پروژه:

```bash
pnpm install --frozen-lockfile
cp .env.example .env
pnpm dev
```

اگر `.env` وجود نداشته باشد، برنامه با مقادیر پیش‌فرض محلی اجرا می‌شود. دستور `cp` را برای راه‌اندازی اولیه اجرا کنید؛ اجرای دوبارهٔ آن فایل تنظیمات محلی را جایگزین می‌کند.

در ترمینال دوم:

```bash
curl -i http://127.0.0.1:3000/health
curl -i http://127.0.0.1:3000/missing
```

پاسخ اول `200` با بدنهٔ زیر است:

```json
{ "status": "ok" }
```

پاسخ دوم `404` با بدنهٔ زیر است:

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Route not found."
  }
}
```

برای توقف، در ترمینال سرور `Ctrl+C` بزنید.

## ساخت و بازکردن لینک کوتاه

در زمان روشن‌بودن سرور:

```bash
curl -i -X POST http://127.0.0.1:3000/api/urls \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/articles/backend?source=test#intro"}'
```

پاسخ `201` و یک کد تصادفی است؛ کد نمونهٔ زیر در هر درخواست متفاوت خواهد بود:

```json
{
  "shortCode": "aB3x9KpQ",
  "originalUrl": "https://example.com/articles/backend?source=test#intro",
  "shortUrl": "http://127.0.0.1:3000/aB3x9KpQ"
}
```

مقدار واقعی `shortUrl` را در مرورگر باز کنید، یا کد واقعی را جایگزین نمونه کنید:

```bash
curl -i http://127.0.0.1:3000/aB3x9KpQ
```

پاسخ `302` و سرآیند `Location` با آدرس اصلی برمی‌گردد. `curl` بدون `-L` انتقال را دنبال نمی‌کند؛ مرورگر آن را دنبال می‌کند. اعتبارسنجی ساختار URL به معنی بررسی وجود صفحهٔ مقصد نیست.

آزمایش خطا:

```bash
curl -i -X POST http://127.0.0.1:3000/api/urls \
  -H 'Content-Type: application/json' \
  -d '{"url":"javascript:alert(1)"}'
```

انتظار: `400` با کد `INVALID_INPUT`. آزمایش‌های بیشتر، از جمله JSON خراب، محتوای بزرگ و ازبین‌رفتن لینک پس از restart، در [راهنمای اسپرینت دوم](docs/sprint-02.md) آمده‌اند.

## دستورهای پروژه

| دستور               | کاربرد                                      |
| ------------------- | ------------------------------------------- |
| `pnpm dev`          | اجرای توسعه و شروع دوباره پس از تغییر فایل  |
| `pnpm typecheck`    | بررسی نوع‌ها در کد و تست‌ها                 |
| `pnpm test`         | اجرای تست‌های خودکار                        |
| `pnpm format`       | قالب‌بندی فایل‌ها                           |
| `pnpm format:check` | بررسی قالب‌بندی بدون تغییر فایل‌ها          |
| `pnpm build`        | تولید JavaScript در `dist/`                 |
| `pnpm start`        | اجرای نسخهٔ ساخته‌شده؛ ابتدا build لازم است  |
| `pnpm check`        | بررسی قالب، نوع‌ها، تست‌ها و build به‌ترتیب |

`tsx` کد TypeScript را هنگام توسعه و تست اجرا می‌کند؛ بررسی نوع‌ها را `tsc` انجام می‌دهد. عبور از اجرای توسعه به‌تنهایی به معنی درست‌بودن نوع‌ها نیست.

اجرای نسخهٔ ساخته‌شده:

```bash
pnpm build
pnpm start
```

## ساختار

```text
src/
  app.ts                        # ساخت و اتصال اجزای Express
  server.ts                     # تنظیمات، بازکردن پورت و توقف سرور
  config/
    env.ts                      # خواندن و اعتبارسنجی تنظیمات
  errors/
    app-error.ts                # خطای قابل‌انتظار با status و code
  links/
    link-service.ts             # ساخت لینک، تولید کد و مدیریت برخورد
    link-store.ts               # نوع Link و ذخیره‌ساز Map
    validate-url.ts             # اعتبارسنجی ورودی و استانداردسازی URL
  routes/
    health.ts                   # مسیر GET /health
    links.ts                    # مسیرهای ساخت لینک و Redirect
  middleware/
    not-found.ts                # پاسخ JSON برای مسیر ناموجود
    error-handler.ts            # مدیریت خطای پیش‌بینی‌نشده
tests/
  app.test.ts                   # قرارداد HTTP و مدیریت خطا
  env.test.ts                   # تنظیمات معتبر و نامعتبر
  links.test.ts                 # جریان ساخت و انتقال، ورودی‌ها و برخورد کدها
docs/
  sprint-01.md                 # توضیح فارسی جریان اجرا و تصمیم‌ها
  sprint-02.md                 # توضیح کوتاه‌کننده و آزمایش‌های دستی
.env.example                    # نمونهٔ تنظیمات قابل‌اشتراک
package.json                    # وابستگی‌ها و دستورهای پروژه
pnpm-lock.yaml                  # نسخه‌های حل‌شدهٔ وابستگی‌ها
pnpm-workspace.yaml             # تنظیمات pnpm 12؛ پروژه تک‌بسته‌ای است
tsconfig.json                   # بررسی سخت‌گیرانهٔ نوع‌ها
tsconfig.build.json             # تنظیمات خروجی قابل‌اجرا
```

## تنظیمات محیط

| متغیر             | پیش‌فرض                 | مقدار معتبر                                                   |
| ----------------- | ----------------------- | ------------------------------------------------------------- |
| `NODE_ENV`        | `development`           | `development`، `test` یا `production`                         |
| `HOST`            | `127.0.0.1`             | نشانی IPv4 یا IPv6 معتبر                                      |
| `PORT`            | `3000`                  | عدد صحیح از ۱ تا ۶۵۵۳۵                                        |
| `PUBLIC_BASE_URL` | مشتق از `HOST` و `PORT` | مبدا عمومی HTTP(S) بدون مسیر، query، fragment یا اطلاعات ورود |

`127.0.0.1` دسترسی را به همین دستگاه محدود می‌کند. برای دریافت درخواست از رابط‌های شبکهٔ IPv4، مقدار `HOST` را آگاهانه به `0.0.0.0` تغییر دهید.

`HOST` و `PORT` محل گوش‌دادن سرور هستند؛ `PUBLIC_BASE_URL` مبدا لینک‌هایی است که به کاربر برمی‌گردانیم، مثلاً `https://short.example.com`. اگر آن را تنظیم نکنید، برای توسعه از آدرس و پورت محلی ساخته می‌شود؛ آدرس‌های bind عمومی `0.0.0.0` و `::` به `127.0.0.1` تبدیل می‌شوند. اگر پورت را تغییر دادید، مقدار صریح `PUBLIC_BASE_URL` را نیز متناسب تنظیم کنید. این مبدا از هدر `Host` درخواست ساخته نمی‌شود.

Node.js فایل `.env` را با گزینهٔ `--env-file-if-exists` می‌خواند؛ به `dotenv` نیاز نداریم. متغیرهایی که قبلاً در محیط فرایند تنظیم شده‌اند بر مقادیر فایل اولویت دارند. `.env` وارد Git نمی‌شود؛ نمونهٔ فاقد اطلاعات محرمانه در `.env.example` نگهداری می‌شود.

اگر خطای `EADDRINUSE` دیدید، پورت در اختیار برنامهٔ دیگری است؛ آن برنامه را متوقف کنید یا `PORT` را تغییر دهید. تنظیمات نامعتبر باعث خروج با کد ۱ می‌شوند. فایل‌های خروجی `dist/` را ویرایش نکنید؛ منبع تغییرات `src/` است.

## قرارداد فعلی HTTP

| درخواست یا اتفاق                                       | وضعیت | نتیجه                                                  |
| ------------------------------------------------------ | ----- | ------------------------------------------------------ |
| `GET /health`                                          | `200` | JSON سلامت فرایند با `Cache-Control: no-store`         |
| `HEAD /health`                                         | `200` | همان سرآیندها بدون بدنه؛ رفتار استاندارد Express       |
| `POST /api/urls` با JSON معتبر                         | `201` | کد ۸ کاراکتری، آدرس اصلی استانداردشده و لینک کوتاه     |
| `GET /:code` برای لینک موجود                           | `302` | مقصد در `Location`، به همراه `Cache-Control: no-store` |
| کد معتبر ولی ثبت‌نشده                                  | `404` | `LINK_NOT_FOUND`                                       |
| ورودی نامعتبر / JSON خراب                              | `400` | `INVALID_INPUT` / `INVALID_JSON`                       |
| بدنهٔ بزرگ‌تر از ۸ KiB                                  | `413` | `PAYLOAD_TOO_LARGE`                                    |
| نوع محتوای نادرست، فشرده‌سازی یا charset پشتیبانی‌نشده | `415` | `UNSUPPORTED_MEDIA_TYPE`                               |
| ده تلاش ناموفق برای تخصیص کد یکتا                      | `503` | `CODE_GENERATION_FAILED`                               |
| مسیر یا متد ثبت‌نشده، مانند `POST /health`             | `404` | خطای JSON با کد `NOT_FOUND`                            |
| خطای پیش‌بینی‌نشده پیش از ارسال پاسخ                   | `500` | پیام عمومی برای مصرف‌کننده و ثبت جزئیات در لاگ سرور    |

در این اسپرینت پاسخ جداگانهٔ `405 Method Not Allowed` پیاده نشده است. مسیر سلامت فقط زنده‌بودن سرویس HTTP را نشان می‌دهد؛ دربارهٔ سلامت دیتابیس یا قابلیت ساخت لینک ادعایی نمی‌کند.

کدها ۸ کاراکتر و به بزرگی و کوچکی حروف حساس‌اند؛ حروف انگلیسی، ارقام، `-` و `_` مجازند. مسیر تک‌بخشی با قالب معتبر به‌عنوان کد لینک بررسی می‌شود؛ قالب نامعتبر به پاسخ عمومی `NOT_FOUND` می‌رسد. مسیر سلامت زودتر ثبت می‌شود تا تحت تأثیر مسیر عمومی Redirect قرار نگیرد.

ورودی `url` باید رشتهٔ آدرس مطلق HTTP(S)، بدون اطلاعات ورود و حداکثر ۲۰۴۸ کاراکتر پیش و پس از استانداردسازی باشد. فاصلهٔ ابتدا و انتها حذف می‌شود؛ از `new URL()` برای استانداردسازی استفاده می‌کنیم، بنابراین `https://example.com` به `https://example.com/` تبدیل می‌شود. درخواست تکراری برای یک مقصد می‌تواند لینک کوتاه جدید بسازد. بدنه باید JSON فشرده‌نشده با UTF-8 باشد.

## مسیر مطالعه

[راهنمای اسپرینت اول](docs/sprint-01.md) مبانی HTTP و ساختار اولیه را توضیح می‌دهد. سپس [راهنمای اسپرینت دوم](docs/sprint-02.md) را برای جریان کامل کوتاه‌کردن و بازکردن لینک بخوانید. خروجی `pnpm check` باید بدون خطا باشد.

محدودیت فعلی: داده‌ها فقط در حافظهٔ همین فرایند نگهداری می‌شوند و با restart، حتی restart خودکار `pnpm dev` پس از تغییر کد، از بین می‌روند. چند نمونهٔ سرور دادهٔ مشترک ندارند و تعداد لینک‌ها با مصرف حافظه رشد می‌کند. قدم بعد، PostgreSQL با migration و محدودیت یکتایی در دیتابیس است.
